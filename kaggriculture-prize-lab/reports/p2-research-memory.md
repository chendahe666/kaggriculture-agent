# P2 研究记忆增量（项目证据，不覆盖 MR-1）

日期：2026-09-12。状态：local_evidence。通用 competition-research skill 仍为 0.1.1；本轮没有训练 LLM 权重，也没有跨赛验证这些新经验。冻结的 MR-1 文档和数值快照保持原样。

## P2-L1：实际提交入口是被测算法的一部分

范围：当前 Kaggle Python `get_last_callable` 加载器。重新定义已有 `agent` 名称不会把字典键移到末尾；追加的其他 helper 可能被当作入口。P2a 的四份原件复现了这个问题，显式调用 `module.agent` 的开发收益不等于文件可提交。

证据：`tests/test_terminal_entrypoint.py` 与 `reports/p2a-20260912-report.md`；修订文件使用最后追加的唯一入口名，并以实际文件路径整局检查。后续候选必须冻结最终文件哈希、加载方式和资源测量范围；不能给修复后的新 hash 冒用旧文件成绩。

失效条件：官方加载器或文件构建方式改变后重新测试。此规则不声称所有平台都采用相同入口约定。

## P2-L2：改写动作必须处理策略自己的交易记忆

范围：COK `_FR_STATE`、`_META_STATE.h5_due`、`prev_action` 等状态与 P2 等待卖出模块的接口。源策略记下了提前销售，而外层随后取消销售，可能留下未实际发生的偿还义务。只保证返回动作合法不够。

证据：`tests/test_terminal_timing_safety.py` 复现旧版新增幽灵债及下一观测的销售影响。安全附加层只撤销本回合新增且未被实际可执行销售支持的债，保留入窗前债务、正常到期消耗及其他状态，并记录最终动作。

提示约束：每个外层 action override 都应说明谁拥有内部状态、何时提交、失败如何对账。不能简单清空整个状态来通过局部测试。失效条件：基线账本、实际市场执行顺序或预售语义变更。机制修复不自动证明胜率提高。

## P2-L3：融资按真实订单顺序发生

范围：官方顺序执行市场订单。零现金、先卖奶再雇工再卖麦的反例中，后置麦销售不能为前面的雇工追溯融资；旧版取消奶销售会把一次成功雇工变为失败。

证据：同一安全测试文件的实际引擎反例，安全层以前置现金保守保护剩余雇工。失效条件：官方成交/融资顺序变化。这个保守规则不是现金管理最优解，不排除将来用逐指令现金流模型减少不必要回退。

## P2-L4：前置状态等价与运行预算等价分别记录

旧状态指纹包含 `remainingOverageTime`。P2b 有三条原始指纹异常；机器负载是有根据但未完全核实的解释，因为旧记录没有完整前置快照。主结果不删除这些行，也不伪造旧 canonical 指纹。

新 runner 同时记录原始指纹、排除耗时余额的 gameplay 指纹、本方逐调用 wall/CPU。两者都保留：忽略预算可以检查玩法是否相同，但不能据此把资源失败删掉。内部函数耗时不含全部加载/框架成本，真实文件路径测试另报。失效条件：观测字段或计时机制变化。

## P2-L5：更多搜索与更多金币都不能单独完成晋级

P2a 深度 1/2/3 的搜索量和平均金币差呈预算曲线，但原16场胜负完全相同。P2b 联合机制比两个单独模块多出正金币交互，40场官方胜分改善却仍仅来自两场镜像平转胜；其他四类对照已全部获胜。

证据：`reports/p2a-20260912-report.md`、`reports/p2b-20260912-report.md`、`results/terminal-20260912/p2b-interactions.json`。限制：有限开发集、五个暂定类型中有弱对手，不能推出未知强手收益。重开条件是新任务价值模型、实质不同的响应策略或更早时域的已诊断机会，而非继续刷同一组 seed。

## P2-L6：稀疏胜负变化要检查区间方法的漏损失风险

配对 bootstrap 只重采样已经观测到的变化。若罕见大退化尚未出现，可能给出误导性的正下界。P2 在确认集未打开前保存反例并修订正式门禁：有界 seed block 的固定 mixture e-test，以及家族退化概率上界；bootstrap 保留为诊断。

证据：`scripts/paired_release_gate.py`、`tests/test_paired_release_gate.py`、`reports/p2-source-and-validation-audit.md`。这些方法仍依赖固定对手池、新 seed 的抽样假设和正确配对，不解决对手代表性。更严格的方法也需要功效/计算预算检查；不能把门禁保守、单个 pilot 失败说成所有可行研究已经碰壁。后续方法调整必须在新的确认结果打开前说明统计理由，保留旧版本。
