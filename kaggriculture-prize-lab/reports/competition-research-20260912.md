# 从局部补丁到成长型竞赛研究系统

研究日期：2026-09-12 UTC／2026-09-11 America/Chicago。范围：预测型数据比赛、仿真优化比赛、对抗智能体比赛。版本：CR-1。本文是文献研究与方法设计，不是新策略的实测提分报告。

## 执行摘要

高水平竞赛研究不应围绕某个模型名字，也不应被现有代码结构限定。更有价值的核心能力是：正确表达问题，构建代表真实目标的评价，探索机制不同的方法，在有限预算中找到信息量最大的实验，并保存能够被后续证据推翻的记忆。

当前 Kaggriculture 证据支持“局部库存补丁这一组实现没有获得可靠增益”，不支持“规则之外的方法没有必要”。九个候选、296 次仿真覆盖了若干采购和配送改动；这些并不是对规划、模仿学习、价值学习、强化学习或程序搜索的比较。把这轮失败概括为算法空间已穷尽，会把有价值的反例变成错误的搜索限制。[项目 P1 报告](p1-20260912-report.md)

本研究形成三个改变。

第一，baseline 是实验对照，不是架构边界。旧冠军应继续保留，但新候选可以在明确的资源和权限范围内采用不同的状态表示、规划器或学习模型。第二，成长对象必须明确：更新状态模型、价值函数、策略、对手模型、实验选择器或研究记忆，是六件不同的事。第三，研究收益要从“写了多少规则”转向“排除了哪些解释、发现了哪些条件、在未见场景中改善了什么”。

综合判断是：优先探索 **准确模拟器支持的联合规划，与轻量价值／策略学习的组合**；用会反应的对手群体检验它，用 LLM 扩大可执行候选和实验假设的搜索。这是基于现有资源的研究优先级，不是已证明最优架构。大规模深度强化学习保留为可试验方向，但不凭概念先进程度预支其效果。

## 二、先辨认比赛，而不是先选模型

同属 Kaggle，不代表目标和反馈结构相同。预测比赛通常是固定输入到预测输出，预测本身未必改变下一条测试样本；经营智能体的动作会改变库存、未来可行动作、对手收益和后续状态。两者可以共享实验纪律，但不能共享未经改造的验证和集成方式。

|问题类别|主要未知量|合适的探索入口|典型错配|
|---|---|---|---|
|静态预测／排序|标签规律、表示、分布差异|特征与表示、树／线性／神经模型、OOF 集成|随机验证掩盖时间或实体泄漏|
|时序预测|预测时可见信息、未来变化|时序验证、滞后特征、适当容量与校准|把事后统计当预测特征|
|单智能体序列优化|行动长期价值、环境不确定性|规划、价值学习、策略学习及混合|只优化一步代理收益|
|对抗智能体|自己的长期价值加对手反应|对手群体、响应模型、策略人口与反制|只打最新自己或固定录像|
|程序优化／生成|程序空间中的质量与计算代价|候选生成、可执行验证、反馈式搜索|评价器存在捷径却扩大搜索预算|

Kaggriculture 更接近“具有资源约束和部分信息的序列对抗优化”。官方规则引擎能精确计算许多机制，但不意味着线上能够知道对手私有状态、未来商店或未来行为。应把已知机制、可观测状态和需要估计的量分开。这个建模选择决定了哪些部分适合精确计算，哪些适合搜索，哪些值得训练预测器；不是预先宣布全问题都应交给神经网络。[B1](https://algorithmsbook.com/decisionmaking/)、[B2](https://www.masfoundations.org/download.html)

建议每个竞赛首先产出一张契约：目标及聚合方式、预测／行动时点、合法信息、行动空间、转移、结束条件、对手、训练与部署预算、数据及发布许可。缺少这些信息时，讨论“哪个模型最优秀”往往只是在比较名字。

## 三、当前研究限制在哪里

### 1. 正确性约束被误当成方法选择约束

精确核对引擎、禁止未来信息、保持可复现，是必要的证据基础；它们不推出“只能用浅树或规则”。可解释性也有多个层次：能够解释一个状态为何失败，不要求整个策略只能由人写的条件判断组成。学习到的终端价值可以通过校准、消融和局部敏感性检验，搜索策略可以输出资源与任务轨迹。

因此应保留“先验证实现”的要求，删除“所有简单规则没有余地后才允许试学习”的隐性串行门槛。小规模、受控的异构方法比较，能较早识别表示和容量限制。P5 的渐进训练纪律与 P2 的可扩展方法取向不矛盾：前者防止坏实验，后者防止把好实验长期限制在狭窄空间。[P5](https://karpathy.github.io/2019/04/25/recipe/)、[P2](https://bitterlesson.ai/)

### 2. 用案例解释替代了可学习对象

一场回放显示“仓容冲突”，可以产生机制假设，但还缺少决策问题：在当前信息下，哪批货值得保留、哪个任务应推迟、延迟一个动作会损失多少未来胜算？只有明确这些对象，才能比较规则估价、搜索估价、树模型估价或神经价值函数。

“学到了强手经常种某种作物”与“学到了在当前资源／市场／时间条件下该作物的边际价值”差别很大。前者是频率，后者是可用于行动的条件估计。即使后者预测更准，也要再验证决策是否改善。

### 3. 对手多样性不足限制了结论

现有闭环池只有三个保守来源家族。438个强手公开对局提高了观察覆盖，却没有自动变成438个可响应策略。更多录像不能单独解决反事实问题：当本方换路线时，原选手可能改变采购、销售或投资。[项目 P0 报告](elite-study-20260912-report.md)、[项目宏观报告](macro-20260912-report.md)

下一步不只是继续下载，而是把行为假设变为明确命名的研究代理，保留源码／回放来源区分；同时寻找合法公开的不同实现。研究代理可以模拟抢售、延迟投资或资源竞争，但不能冒称复刻了原作者算法。

## 四、能够真正扩展能力的算法组合

### 1. 准确模拟器 + 联合规划 + 终端价值

最直接的研究对象，是当前合法状态中的可执行任务和资源承诺。对少量候选任务安排进行短期模拟，使用终端价值估计处理视窗之外的结果，再执行一个动作并重算。将“最后补给机会、运输占用、在途商品、市场兑现窗口”放在同一规划状态中，能够直接检验 P1 暴露的耦合。[B1](https://algorithmsbook.com/decisionmaking/)

关键实验不是只增加前瞻长度，而是比较三个受同样部署预算约束的版本：短视窗、覆盖关键截止点的视窗、短视窗加终端价值。若第三种在相同运行时间下更强，才说明学习价值可能在替代昂贵深搜；若深搜始终较好，则继续投资更好的剪枝／候选生成，而不是为学习而学习。

必须记录截断偏差：一个早期建设动作可能短期亏损、后期盈利。仅截取前100步筛选完整经营路线，很可能奖励不投资的策略。便宜评测应减少完整对局数量、使用代表场景或降低搜索宽度，而不是随意改变目标时域。低精度筛选是否保持排序本身也需要检验。

### 2. 模仿不是复制整条动作带

回放可用于学习任务类别、资源估价、行动候选或策略初始化。输入必须能在当时合法获取；数据按对局、版本、时间分组，不能随机拆帧制造大量“独立样本”。训练与测试的差别不仅来自不同局，还来自学生策略自己造成的状态变化。

一个有价值的对照是：只学专家访问的状态，和加入学生偏离状态的纠正数据，谁的闭环失败率更低。但纠正标签需要可调用专家或可信小型求解器。只持有历史录像时，无法询问原强手在一个新局面会怎么做，不能把任意伪标签流程命名为标准 DAgger。[B1](https://algorithmsbook.com/decisionmaking/)

动作准确率只是诊断。多个动作可能等价，同一动作在不同资源承诺下也可能截然不同。最终应以合法闭环结果验收，另外检查训练未覆盖状态、恢复能力、模型不确定性和回退行为。

### 3. 学价值／策略，不重复学习已经准确的机制

官方模拟器已经准确的交易和结算机制，不必默认再用大网络学一遍。更有潜力的学习对象包括有限搜索视窗后的价值、候选行动的优先次序、公开信息条件下的对手响应分布，以及可压缩部署的策略。

强化学习的模型、价值和策略更新可以组合，但必须分别记录误差与收益。规划所用价值函数是内部工具，官方验收仍固定；不能借“评价器自学习”改变权重让当前策略得高分。使用离策略数据、函数近似与自举时，要专门检查不稳定和分布外估计，而不是只画一条上升的训练奖励曲线。[B3](http://incompleteideas.net/book/RLbook2020.pdf)

大规模 RL 的主要未知不是“理论上能不能”，而是在当前样本、模拟速度、动作表示和训练预算下能不能得到有效信号。先测小型策略或价值模型的数据／计算曲线，再决定是否扩大。一个配置失败应归入实现、拟合、泛化、探索、奖励或资源问题之一，而不是直接给整个方法判死刑。

### 4. 对手群体 + 专门寻找弱点的策略

策略改进可能是循环的：A克制C、C克制B、B克制A。只保留最新冠军会遗忘旧弱点。多智能体研究和 AlphaStar 的实践都提示：总体表现好的主策略，与专门揭露其弱点的对手，不应承担同一种训练角色。[B2](https://www.masfoundations.org/download.html)、[P4](https://deepmind.google/blog/alphastar-grandmaster-level-in-starcraft-ii-using-multi-agent-reinforcement-learning/)

建议保存一个小而有意义的策略人口：历史冠军、不同来源家族、可响应的机制代理、专门反制当前候选的版本。记录两两胜负矩阵，同时单独估计近期实际匹配分布。面向实际对手的期望收益，与面对已知最坏家族的保护能力，应分别报告；保守混合不一定最大化实际榜单机会。

发现一个成功反制，证明存在弱点；没有搜到成功反制，不证明不存在。有限人口中的平衡不等于全策略空间的纳什均衡。教材中的无遗憾结论也依赖条件，尤其是固定对手已发生动作的事后基准，不能替代本方改动引起的对手响应。公开稿勘误登记还提醒：理论名字正确，不代表复制的公式实现正确。[第7章勘误](https://www.masfoundations.org/wiki/TWiki/bin/view.cgi/Main/LearningTeachingErrata)

### 5. LLM 程序搜索 + 可执行评价 + 蒸馏

LLM 最适合先进入离线研究环：提出候选表示与规划程序，检查失败，修改代码，利用历史档案选择下一次探索。AlphaEvolve 展示的是程序生成与自动评价相结合的结构；迁移到比赛，需要额外抵御测试泄漏、错误代理指标、候选代码越权与多轮选择偏差。[P3](https://deepmind.google/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/)

如果一个离线昂贵规划器显著更强，可以研究将其决策蒸馏成小模型，或只让小模型缩小线上搜索候选。这样把训练预算和部署预算分开。相反，每回合外部 API 调用、打包本地模型和离线生成代码，是不同方案，必须分别核验比赛联网、时限和打包要求，不能用“接入大模型”混为一谈。

LLM 的语言解释可以指导实验，但不能作为最终胜负裁判。新程序也必须在限制文件、网络和资源的环境中测试。增长依赖评价反馈的真实性；错误评价器配合更强搜索，可能只会更快找到评价漏洞。

## 五、把预算分给能改变决定的实验

实验卡应回答四个问题：现在在两个什么决定之间犹豫？不同解释预测什么？哪个最小实验能区分它们？结果出现后会改做什么？如果所有可能结果都不会改变行动，继续增加这类数据的优先级应下降。信息价值思想适合作为决策框架；没有可靠概率时，使用情景表，不编造收益乘置信度的精确数字。[B1](https://algorithmsbook.com/decisionmaking/)

建议的首轮预算是一个**可调整比例模板，不是已执行计划**：

|用途|初始预算占比|获得什么决定依据|
|---|---:|---|
|正确性、接口及计时基准|15%|候选比较是否有效、部署瓶颈在哪里|
|联合规划／搜索探针|25%|是否受视窗、候选质量、执行接口限制|
|轻量价值或策略学习探针|20%|样本是否含可用信号、学习能否替代部分计算|
|异构对手和针对性反制|15%|收益是否仅来自狭窄对手|
|完整局确认、耦合消融与资源回归|25%|是否值得继续投入或进入下一验证层|

先测模拟速度和工程实现成本，再将比例换成小时和局数。不要在不知道吞吐时承诺数百万局；首次搭建训练接口的时间也必须计入。若预算不足，不把每条路线都做成半成品，而是保留两个最有判别力的探针和一个可信对照。

为每条方法画至少两条关系：主任务结果对训练／搜索预算，以及部署时间对预算。比较固定预算下效果和额外计算的边际收益。早期曲线有希望但绝对成绩尚低，可以保留研究资格；它仍不能替换实测更强的线上冠军。P2 的规模观点在这里转化为一个可测问题，而不是无限扩算力的理由。[P2](https://bitterlesson.ai/)

## 六、全面评价不是堆更多指标

一个评价体系应让指标各有职责。

**契约层**核验动作、信息、资源、依赖和许可；任何主指标增益不能抵消越权特征。**机制层**核验干预覆盖和因果链；例如少采购究竟减少了浪费还是连带减少成交。**任务层**比较官方结果与配对增益，报告赢转输和分组退化。**泛化层**检查时间、对手家族、状态扰动、预算和未见环境。**研究层**检查单位预算内获得的可靠决策，而非只统计候选数量。

统计上，必须区分固定池内的种子变动和面对新对手的未知。整局有719次行动，不意味着719个独立胜负样本；同一来源的多个版本也不能自动增加家族多样性。预测比赛同理，重叠训练集产生的折分数不能简单视为独立观测，其标准差也不能机械除以折数平方根来给出可信区间。[B4 官方重采样实验](https://islp.readthedocs.io/en/latest/labs/Ch05-resample-lab.html)

当本地和公开榜排序相反时，应检查目标分布、样本量、泄漏和版本绑定。域分类器能够帮助发现训练／测试可分辨的特征，但高 AUC 不自动证明标签泄漏，低 AUC 也不能证明不存在条件分布变化。重加权或新切分需在新的目标近似窗口检验，不能根据当前候选成绩倒推评价器。[B5 官方配套代码](https://github.com/PacktPublishing/The-Kaggle-Book/blob/main/chapter_06/adversarial-validation-example.ipynb)

集成也要分类讨论。预测模型可以在合法 OOF 预测上测试误差互补；经营策略却可能承诺了不同农场布局。每回合平均两套动作，不等于集成两套完整策略。整局选择、合法上下文门控和统一蒸馏，是三个需要独立测试的设计。P1 的互补思路有启发，但并不保证模型数量越多越强。[P1](https://medium.com/kaggle-blog/axa-winners-interview-learning-telematic-fingerprints-from-gps-data-768ac9658d18)

评价器的学习必须采用过去拟合、未来验收。若每轮都用同一438局修改模型、权重和研究规则，就只能说明更熟悉这批开发资料，不能称为独立泛化。新鲜留出数据是一种有限资源，应登记每次开启；一旦观察，就不再重新包装成未见样本。

## 七、落回 Kaggriculture：新研究组合而非新神话

以下方法映射到现有 E/V/P/A/G/R track，不篡改历史证据或宣称已经实现。

|研究组合|挂接现有 track|首个可否证实验|关键风险／重开条件|
|---|---|---|---|
|合法状态、资源承诺与任务接口|E/P|影子预测下一事件及最后可行补给／运输时点|预测错误先修模型，不归罪规划|
|联合规划与终端价值|P/V|同预算比较视窗／估价，联合与单模块消融|错误终端价值、执行恢复、抢占现金或动作|
|回放表征与轻量模仿／价值学习|A/P|合法观测学生，与固定策略和搜索教师比较|专家状态分布、标签质量、开过的数据不能验收|
|响应家族与反制人口|G|候选对历史／新家族，检查循环克制和遗忘|家族不足时不得输出未知对手保证|
|离线 LLM 候选搜索|跨 track 研究工具|同预算比较结构性候选与局部参数候选的信息产出|评价捷径、代码权限、选择偏差|
|完整整合与外部回证|R|冻结最终范围，未来闭环与部署回归|未过门禁不上线，GitHub 不等于比赛提交|

当前 `research-state.json` 已登记 Track P 方向批准，但尚未启动新规划器。这个批准与改变线上 baseline、购买算力、提交 Kaggle 是不同权限。本轮完成的是研究框架和 skill，不将上述路线写成已经训练或对局成功。冻结 COK 控制与原有未开留出种子保持不变。

更广义的架构改变，不应该永久被“先完成所有机制”阻塞。可先让不同方法在隔离探针中比较，等决定一套整合范围后再完成整条 track 的耦合和发布验收。否则可能在一条错误表示上无限追求局部完整性。

## 八、成长型 skill 的结构与更新规则

交付的 `competition-research` 把通用推理与项目证据分开。主入口负责问题契约、方法组合、证据阶梯和每轮输出；预测与序列比赛各有路由；来源台账记录真实阅读；记忆文件保存状态、适用范围、反例和推翻条件。

成长应有四种不同记录：文献指导、待验证假设、项目内证据、跨条件证据。退役规则不能静默删除，要保留为何失败。一本书提供理论条件，不等于本项目已验证；某个补丁失败，不等于所有同类算法都失败；一个项目通过，不等于下个项目普遍适用。

更新流程是：提出有范围的修改 → 绑定资料或实测 → 审查相反证据 → 校验结构 → 在新的任务上比较旧版／无 skill 行为 → 检查退化 → 版本记录与安装一致性核对。结构校验器只检查记录完整性，不能自动判定结论为真。前向问答测试只检查研究决策，也不能作为游戏胜率提升证据。

建议优先加入的未来记忆，是可迁移的失败模式和选择原则，例如“截短评测会错排延迟回报方案”“回退策略必须适应已经改变的状态”“改善预测不代表改善决策”。不要把某场某回合、固定牛羊数量、单批排名或项目权限写进通用 skill。

这种成长不是大模型权重训练，也不是关闭对话后继续自改的后台系统；它是可审阅、可回退、有证据的研究知识与工作方法迭代。其价值最终要由未来真实研究质量和比赛结果检验。

## 九、需要持续检验的问题

本研究不能回答“哪一种网络一定拿奖”，也没有证据给出新增 skill 对榜单的预计分数。最重要的开放问题是：合法回放信息能提供多强的可泛化价值信号？联合规划是否优于固定路线的隐含折中？增加对手响应能力后旧收益是否保留？部署预算下，学习模型能否比更宽搜索更划算？

这些问题可以逐个实验，而不需要预先相信某一种范式。下一轮最有价值的产物，不一定是更长的代码，而可能是一个明确答案：真正限制表现的是动作候选、价值估计、资源执行，还是本地对手池。只有知道限制在哪里，更多 token、模拟和数据才能转化为进步。
