# Research portfolio and versioned growth

## Select informative experiments

After a plateau, distinguish formulation, information, representation, credit assignment,
search depth, opponent coverage, implementation and compute bottlenecks. Preserve
competing explanations. Choose an experiment that changes a decision, not another
number on the same development set. Value of information is a decision principle,
not permission to invent precise success probabilities.

Archive parent/version, hypothesis, code hash, dependencies, data/opponents, evaluator
version, compute, complete results and decision. Preserve failed proposals. Allocate
some budget to structurally different methods, not only slight champion mutations.
Short games and low-cost proxies need ranking calibration; delayed-payoff methods
need full episodes. Freeze criteria before spending confirmation data.

LLMs can formulate hypotheses, generate legal features/policies, write search code,
inspect failures and propose experiments. Automated program search requires executable
checks and an evaluator resistant to shortcuts. Separate generation from confirmation;
prevent candidates reading private tests, secrets or unauthorized files/network. Use
deterministic checks for rules and measured outcomes for strength. LLM prose approval
does not replace either. This design is inspired by P3; it is not an implementation
of AlphaEvolve or evidence that a named LLM wins this contest.

Offline assistance, remote online APIs and bundled local inference are different
proposals. Check current rules/resources for each. Do not buy API/GPU resources or
upload private data just because the user wants better scores.

## Learn without laundering evidence

- `literature_guidance`: source-backed advice with assumptions; not a local result.
- `hypothesis`: proposed causal/algorithmic improvement awaiting tests.
- `local_evidence`: measured in a specified task, engine and population.
- `cross_context_evidence`: independently supported across claimed contexts, not universal.
- `retired`: contradicted, obsolete or superseded; retain why and by what.

Each lesson has ID, claim, scope, evidence links, limitations, falsification, status,
version and validation records. Record actual reading coverage and access date;
distinguish full text, abstract, preview and companion code. Check official errata
before implementation. Do not redistribute books/posts in the skill.

A counterexample defeats an unconditional claim but does not prove its inverse.
Mechanism tests do not establish policy rankings. Recomputing old data is not new
validation. Do not promote project thresholds to global rules or enlarge a claim's
scope merely by adding it to a prompt.

## Update procedure

1. Propose a narrow lesson diff with motivation and counterexample/expiry condition.
2. Attach evidence; retain conflict and previous versions in Git.
3. Separate generic insight from project details. No private data, hardcoded match IDs
   or one project's permissions as universal instructions.
4. Run the memory validator; it checks structure/status requirements, not truth.
5. Forward-test affected decisions on realistic untouched cases against the prior
   skill or no-skill control under equal model/resources when available. Grade
   substance, not keywords. Preserve complete outputs.
6. Inspect regressions and human feedback. A few prompt tests do not demonstrate
   competition-score gains. Record actual limitations, even a tied comparison.
7. Update this installed skill only within granted scope, verify hashes and record
   its source version. No background mutation or model-weight training is implied.

## Round report template

- Contract, track, hypothesis and strongest competing explanation.
- Changed/frozen components, shared resources and implementation checks.
- Data/opponents, metric, budget, stopping rule and holdout use.
- Actual coverage, mechanism, full objective, uncertainty and regressions.
- First causal divergence; remaining observation or unidentifiability.
- Retain/reject/inconclusive/needs authority; next informative test.
- Memory diff, report/version locations and actual Git/submission status.
